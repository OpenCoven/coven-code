# Model-round budgets

`--max-turns N` selects a positive finite budget for one query, including a query started with `--resume`. A round is one engine model dispatch and its tool batch, not a user chat message or an individual tool call. An explicit run limit wins over the selected agent's `max_turns`, then the caller's contextual default, then `MAX_TURNS_DEFAULT` (10). An agent's null limit inherits. Zero, negative, nonnumeric and overflowing values are rejected; there is no unlimited mode. Rust callers express an explicit selection with `QueryConfig::max_turns_override`; `max_turns` remains the inherited/contextual limit.

The engine checks the boundary before starting another round. All tools selected in the last permitted response settle and their results remain in history before exhaustion is reported. A successful final response on the last permitted round completes normally. Local provider/authentication or goal rejection before dispatch consumes no round. Outer stalled-stream retries and fallback dispatches consume rounds; retries internal to a provider transport, compaction requests and a delegated CLI's own internal work are separate from this engine-loop allowance. Nested agents have their own limits. Turn budgets do not change dollar, token, time, goal, credential or permission limits.

## Capability and wire extension

This is an additive run-budget extension to engine contract v1, with its own `run_budget_version: 1`. Existing flags, event kinds, terminal `subtype` values, `is_error` interpretation, semver-only `--version` output and process exit codes remain usable by v1 consumers. No released package version is claimed to include the extension. Probe the actual resolved executable with `coven-code --run-budget-capabilities`; this standalone probe exits 0 with one JSON object and does not load credentials, migrate state, contact a provider or launch work:

```json
{"engine_contract_version":1,"run_budget_version":1,"flag":"--max-turns","minimum":1,"maximum":4294967295,"default":10,"exhausted_outcome":"turn_budget_exhausted","one_shot_exhausted_exit_code":1,"stream_eof_exit_code":0}
```

Stream-input `system.init` adds `run_budget_version` and `turn_budget: {max_turns, source}`. Query result frames add `run_budget_version`, `turn_budget: {max_turns, source, consumed}` and `continuation: {session_id, resumable}`. The source is `explicit`, `agent`, `configured` or `default`. Counts belong to this invocation and do not read the tool display counter shared with nested work. Exhaustion has this terminal shape (duration and partial output are format-dependent):

```json
{"type":"result","subtype":"error_during_execution","is_error":true,"outcome":"turn_budget_exhausted","run_budget_version":1,"session_id":"engine-session-id","num_turns":10,"turn_budget":{"max_turns":10,"source":"explicit","consumed":10},"continuation":{"session_id":"engine-session-id","resumable":true},"error":"Model-round budget exhausted (10/10); work is unfinished."}
```

Exhaustion is unfinished work, never successful task completion or a provider/API failure. One-shot text, JSON and stream-JSON output exit 1 when exhausted. A long-lived stream-input process reports the error result, remains available for another input frame, and exits 0 on stdin EOF; consumers must settle from each result rather than the eventual process status. The existing coven-github result-file contract remains v3: model-round exhaustion follows its existing errored outcome, not its USD-budget outcome. ACP maps local turn exhaustion to `MaxTurnRequests`; background agents and scheduled tasks report unfinished work rather than completion. Provider/authentication errors and cancellation remain separate outcomes.

## Continuation and its limits

Ordinary print and stream-input queries save the updated engine transcript before publishing a resumable result. The save includes partial assistant output, tool-use blocks and their completed results, subject to existing context compaction and result budgeting. `continuation.resumable` is false if saving fails or a query task panicked and its complete working transcript cannot be confirmed. Workspace-scoped Chat runs retain host-owned continuity and advertise false for engine resume; this extension does not widen workspace authority. Existing session storage's atomic-replacement and crash-durability limits still apply. A forced process kill or power loss before persistence is not covered by a resumable receipt.

Resume with `--resume <session_id> --max-turns N` and a continuation prompt, using the saved working directory as `--cwd` when necessary. New sessions persist a canonical absolute directory. Saved relative or missing directories are ambiguous and refused, and directory validation errors identify the saved path. Text exhaustion prints the saved session ID and a quoted resume command only after confirmed persistence and when engine resume is available; otherwise it explicitly reports that engine continuation is unavailable. `--continue` and `--resume` without an ID select the most recently saved session. Each query receives a fresh allowance. Missing, corrupt or identity-mismatched sessions and a different working directory fail before model work; the engine must not substitute a new conversation. In-process stream continuation retains the same transcript and session ID. This preserves completed work as model context; it is not a transactional exactly-once guarantee if a model deliberately requests the same operation again or a tool is interrupted after an unknown side effect.

## Consumer coordination and acceptance

[Engine #497](https://github.com/OpenCoven/coven-code/issues/497) owns this producer. [Coven #1779](https://github.com/OpenCoven/coven/issues/1779) owns typed `coven run --max-turns`, adapter capability negotiation, exact forwarding before the prompt delimiter, effective-budget reporting and result/session settlement. [Chat #652](https://github.com/OpenCoven/chat/issues/652) owns preference/host validation, applied-budget disclosure, exhausted/continuable presentation and native qualification. Its proposed finite default is 50 rounds: more headroom for tool-heavy work while retaining a stop. Consumers must visibly reject unsupported explicit requests and require the actual runtime capability; neither prompt text nor a package-version assumption applies a budget.

`cargo test -p claurst --test run_budget` uses real engine processes, a loopback deterministic Anthropic stream and actual filesystem tools. It proves eleven-round completion with budget 12, ten requests with budget 10, exact persisted restart identity/history and no repeated ledger writes, precedence, invalid values, missing-resume refusal, save-failure disclosure and offline capability detection. Query tests exercise the same cancellation token used by Stop after eleven rounds, retaining tool results and partial output, and distinguish query accounting from a child's display counter. These do not prove installed Chat → Coven → engine behavior, process-signal Stop, Windows tools or native/human acceptance. Those remain downstream qualification gates; no release, installation, pin or permission-policy change is part of this producer.
